# glibc-neutered

## Summary

A small, fixed policy patch set for Wolfi glibc, for Werewolf appliances. Applications keep public environment access; glibc ignores implicit configuration and rejects optional native-code injection routes.

## Background

The [audit](glibc-vuln-audit.md) inventories recent glibc and analogous libc vulnerabilities. [Werewolf's design](docs/design/glibc-neutered.md) selects five protection mechanisms. Code integrity for remaining native loading requires Werewolf IPE; PostgreSQL setup needs separate changes.

## Goals

- Four small source patches plus existing nscd configure switches implement five protections.
- Preserve optimized CPU dispatch, malloc/tcache/arenas, threads, ordinary DNS, and public `getenv`/`secure_getenv`.
- Retain every current Wolfi hardening flag, compiler environment, upstream patch, and ABI/test gate.
- Follow Wolfi with pinned inputs and fail closed on patch drift.

## Non-Goals

- A general distribution libc, arbitrary runtime opt-outs, or a promise to prevent every RCE.
- Production rollout before application, IPE, performance, and package-update checks pass.

## Detailed design

| Protection | Implementation |
| --- | --- |
| Environment configuration | Private-header redirect and startup gates; preserve getters, select C locale, freeze hardened defaults and fail permissive path fallbacks. |
| Loader injection/search overrides | No preload/audit environment, file, CLI, or ELF activation; no CLI library-path substitutes. |
| NSS | Built-in files/DNS only; external module loading fails. |
| Converters | Built-in graph/aliases only; no external discovery, cache, or converter DSO. |
| nscd | `--disable-build-nscd --disable-nscd`. |

Install Python and the pinned requirements in a virtual environment. `make check derive` verifies provenance and creates `build/glibc.yaml` and its context. `make prepare` fetches the locked source and checks each upstream and policy patch without fuzz. Install pinned Melange with `python3 scripts/install-melange.py --dest build/tools/melange`.

On macOS, install QEMU and bsdtar, then run `WEREWOLF_BUILD=../werewolf/build/aarch64 make build`. Use Werewolf's existing build directory containing `vmlinuz` and `kernel/x/lib/modules`; its Alpine kernel boots a fresh guest generated by the pinned Melange. Modules are appended under `usr/lib/modules`, preserving the guest's loader symlink. The glibc build uses Wolfi's recipe and toolchain inside that guest. Runner, kernel, and guest provenance accompanies the packages.

On Linux with bubblewrap, `sudo make build` uses the same runner as Werewolf CI. Without bubblewrap it uses the Alpine/QEMU path above. `ARCH=x86_64` or `ARCH=aarch64` selects the package architecture; release CI uses native hosts for both. Build resources use `MELANGE_CPU` and `MELANGE_MEMORY`, defaulting to four CPUs and 8 GiB.

`upstream.yaml` and `upstream/` are byte-for-byte Wolfi inputs, authenticated by `upstream.lock.json`. `scripts/derive.py` is the packaging delta; generated files stay under `build/`. `patches/series` fixes application order. Each patch names its purpose, base, policy status, and evidence; [patch maintenance](docs/design/patch-maintenance.md) explains rebasing. No downstream source fork or permissive build is maintained.

Policy patches retain glibc's LGPL-2.1-or-later licensing; copied Wolfi inputs retain their upstream license. License texts are in `LICENSES/`. This repository's own tooling uses the root `LICENSE`.

GitHub Actions checks native x86_64/aarch64 package builds. Daily refresh proposes a reviewed PR; it never silently rebases patches or merges. Passing main builds emit immutable **candidate prereleases**, containing APKs/indexes, CI signing public keys, pins, patches, and hashes. Ephemeral CI keys do not establish production trust. [Release conditions](docs/release-notes.md) separate candidate emission from deployment.

The [patch security review](docs/design/patch-security-review.md) records every removed activation path, retained safeguard, corrected fallback, and remaining release blocker.

The [compiler comparison](docs/design/compiler-hardening.md) records current Wolfi/OpenSSF protections and additional candidates. Extra flags need compatibility and performance evidence before entering release builds. Plain local GCC builds are patch validation, not proof of Wolfi toolchain parity.

## Drawbacks

Implicit environment semantics change: bare command lookup fails, options/patterns use strict defaults, temporary-name lookup needs an explicit directory, and HOME expansion uses account data. Locale is C, not C.UTF-8; explicit application locale requests remain separate. External NSS, UTF-16/legacy converters, injection-based profilers, and nscd are unavailable. Applications must adapt rather than add opt-outs.

## Alternatives Considered

- Launcher sanitation alone misses later environment mutation and non-environment loading.
- Public getenv interposition breaks application configuration and misses loader scans.
- A hand-maintained recipe or a source fork increases update drift; derive from the unchanged upstream recipe.

## Security Considerations

Normal dependencies and explicit `dlopen` remain. Production IPE must reject untrusted executable mappings from those paths. Memory corruption, trusted-code reuse, and interpreted commands are separate risks. Patches complement upstream fixes and Werewolf privilege boundaries.

## Reliability Considerations

Injection probes verify actual constructor execution in a positive control, then require denial on disabled routes. Public environment APIs, C locale, static startup, built-in NSS/conversion, threads, backtrace, and C++ exceptions are checked. Keep upstream failures and raw logs for review; never suppress a whole suite. Both native architectures, required workloads, stable APK trust, and coherent libc/loader updates must pass before production promotion.
